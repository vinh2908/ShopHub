# ADR-008 — Adapter cho cổng thanh toán và đơn vị vận chuyển

- **Status:** Accepted
- **Truy vết:** ASR4 (về mặt modifiability); QA4

## Context

ShopHub phải tích hợp cổng thanh toán (VNPay/MoMo giả lập) và vận chuyển (GHN/GHTK giả lập), và phải thêm được cổng hoặc đơn vị vận chuyển mới trong ≤ 3 ngày công mà không sửa logic đặt hàng cốt lõi.

## Options considered

1. **Gọi trực tiếp API của từng nhà cung cấp từ code đặt hàng:** Nhanh lúc đầu, nhưng mỗi lần thêm nhà cung cấp mới phải sửa code đặt hàng, và logic đặt hàng bị dính với định dạng riêng của từng nhà cung cấp.
2. **Adapter per provider + interface chung (được chọn):** Định nghĩa interface chung cho Payment (charge, refund, query status) và cho Shipping (create shipment, track, cancel). Mỗi nhà cung cấp có một adapter riêng chuyển đổi giữa interface chung và API riêng của nhà cung cấp đó.
3. **Anti-Corruption Layer đầy đủ với canonical model riêng:** Mạnh hơn adapter đơn thuần, phù hợp khi các nhà cung cấp có mô hình dữ liệu rất khác nhau, nhưng phức tạp hơn và chưa cần thiết ở quy mô đồ án nếu interface chung đã đủ.

## Decision

Chọn adapter per provider với interface chung. Ở M4, các adapter gọi tới mock payment và mock shipping có thể cấu hình tỷ lệ lỗi, để kiểm chứng bước bù trừ của Saga. Khi thêm nhà cung cấp mới, nhóm chỉ thêm một adapter mới và đăng ký nó, không sửa Ordering.

## Consequences

- **Tích cực:** Đạt mục tiêu tích hợp ≤ 3 ngày công trong kịch bản kiểm chứng của nhóm; logic đặt hàng không bị ô nhiễm bởi định dạng riêng của từng nhà cung cấp.
- **Tiêu cực:** Interface chung phải được thiết kế cẩn thận từ đầu. Nếu interface thiếu một trường mà một nhà cung cấp cần, nhóm sẽ phải sửa interface và tất cả adapter.
- **Quy tắc kiểm chứng:** Ở M4, nhóm phải chứng minh bằng code rằng thêm một mock provider mới không cần sửa file thuộc Ordering.
